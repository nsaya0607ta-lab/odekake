# かくれ漢字（ミニゲーム GAME 06）

大きな漢字の中にかくれている、べつの漢字をさがすパズル。中国の「天天拼詞王」の遊び方を参考にした独自のゲームで、
名前・ゲーム・問題データはこのアプリ用に作成。**「感」「漢」「称」「森」「明」「思」「想」「意」「語」「謝」「休」「体」「早」「星」「秋」「晴」「岩」「花」「苗」「男」「町」「村」「困」「湖」の24問**。ステージ4〜24の筆画はKanjiVG（CC BY-SA 3.0）を座標変換して使用し、出典と原図を設定画面から確認できる。

## 1. 遊び方

- まんなかの大きな漢字は、はじめは全部**灰色**。線（筆画）をタップすると**黒く**なる（もう一度タップで灰色にもどる。指をすべらせるとまとめてえらべる）。
- 黒くした線が漢字になったと思ったら **OK**。合っていれば答えの一覧に入る。
- **見つける字は小学校で習う字（教育漢字）だけ**。これを全部見つけるとクリア（ユーザー指定）。
- 小学校で習わない難しい字は **🔒シークレット枠**。いくつあるかは見せる（中身は見つけるまで🔒）。クリアには入らず、
  クリアのあともつづけてさがせる。シークレットまで全部見つけると「コンプリート」でラウンドがおわる。
- 「けす」でえらんだ線を全部灰色にもどす。まちがえたときは、えらんだ線はそのまま残る（少し直して、もう一度答えられる）。
- ヒント（青コイン）：読み方 10・画数 10・一部を見る 20（答えに使う線の半分未満を、本当の位置で光らせる）・答えを開く 40。
- スキップ：答えと解説を見て終わり。報酬なし・連続クリアが切れる。

## 2. 正解判定のしくみ（いちばん大事）

- 正解は **ステージデータに登録した答えの「筆画の組」（`strokeSets`）と、えらんだ筆画がぴったり同じ** ときだけ（`judge.ts` の `judgeStrokes`）。
  文字の入力・文字列の検索は使わない。1本でも多い・少ないと不正解。えらんだ順番は関係ない。
- 取り出し方は2つ（`ExtractRule`）
  - `component`：部品をそのまま（感 → 心・口・咸）
  - `strokes`：線をえらぶ。線の**形と位置はそのまま**で、動かしたり曲げたりしない（感 → 一・戈・戌・戊・厂・弋）
  - `loose`：**見立て**（ユーザー指定で条件を少しゆるめた）。線の**長さ・比率・曲がりぐあい・はねの有無は問わない**。
    ただし **線の本数・向き（↙か↘か）・まがるかどうか・交わる／つく／はなれる・上下左右の位置関係** は守る（感 → 二・三・八・乂）。
    横画より上への突き出しなど、字に必要な部分も省かない。木から縦画を外した3画は、突き出しが欠けるため大にはしない。
    点と横画はべつの画（戌と戍は見立てでも別）。テストでは `structures.ts` の `LOOSE_KIND_GROUPS`（右払い〜斜め鉤、縦曲がり〜斜め鉤、縦〜縦鉤）だけを同じ種類とみなす。縦〜縦鉤は小さなはねの有無だけを見立てる「称 → 下」に使う
- 同じ字が何通りかで取り出せるときは `strokeSets` に全部書く（感の「一」は 1・3・6画目のどれでもよい）。同じ部品が複数ある場合も全箇所を受け付ける。
- 曰は正解から外し、日だけに統合する。同じ画の組の正解は一字だけ。人／入・土／士のような字は、字を区別する形・横画の長さを実際の字形で判断する。森の払い2本は人、思の横画2本と縦画は士だけを正解にする。ヒントで開く字も一字だけ。
- 木が偏で点の形になる字形差は、字ごとに `STROKE_STRUCTURE_VARIANTS` に明記する。点と右払いをすべての字で同じ種類にすることはしない。
- `verification.status` が `verified` の答えだけ判定に使う。`pending` の答えと同じ組をえらんだときは「確認中」と出し、正解にしない。
- 全部の線（出題漢字そのもの）は答えにならない。丶・丿のような**部首だけの形**も答えにしない（解説の「おしい字」に理由を書く）。
- 1本ちがいなら「あと1本たりないかも／1本多いかも」とだけ出す（どの答えかは言わない）。
- 答えの `grade`（小学校で習う学年 1〜6。習わない字は null）で、見つける字かシークレットかが決まる。
  学年は `data/grades.ts`（学年別漢字配当表。2020年度から）とテストで照合する。
- 字形の基準は日本の常用漢字（新字体）の筆順・字形。中国の字形とちがう字を出すときは、日本の字形で `strokes` を描く。
  旧字体・異体字は答えにしない（新字体で登録する）。

当たり判定（`stroke-board.tsx`）：指の位置から**それぞれの筆画の線そのもの**までの距離をはかり、いちばん近い画を選ぶ
（SVG の path を 1.2 単位ごとの点に分けて測る。線から 7.5 単位以内＝盤の幅の 7.5%）。交わっている画（感の1画目と7画目）でも近いほうが選ばれる。
画面読み上げ・キーボード用に、画ごとのボタン（見た目はかくす）もある。

## 4. 点数・報酬（いまの数字）

| 項目 | 数字 |

| まちがい | 点は減らない。連続ボーナスが切れるだけ。星も減らない |
| 星 | ★3 ヒントなし／★2 ヒント2回まで・開いていない／★1 クリア（見つける字に使ったヒントだけで決める。シークレットのヒントは関係ない） |
| シークレット | 点数は見つけやすさのとおり。そのステージではじめて見つけた字だけ青コイン +10（`SECRET_COINS`）。クリアの報酬は1ラウンド1回（`rewardedAt`） |
| クリア報酬（初回） | 青コイン `reward.coins`×（★3 1.5／★2 1.25／★1 1）、経験値 `reward.exp` + 見つけた数×5 |
| クリア報酬（2回目から） | `replayCoins`・`replayExp` + 見つけた数×5 |
| 青コイン残高 | アプリ共通。開始時の追加配布はなし |
| ログインボーナス | 1日目 20、連続で +5 ずつ（最大 50）。日本時間で日付を切りかえ |
| レベル | 次のレベルまで 50 + Lv×30。上がるたびに 10 + 新Lv×5 枚 |
| 称号 | Lv1 漢字初心者・Lv3 漢字研究家・Lv6 漢字博士・Lv10 漢字名人・Lv15 漢字達人 |
| 実績 | 初めての正解・初めてのクリア・ノーヒントクリア・全問正解（まちがい0・ヒント0で見つける字を全部）・連続クリア（スキップせず3回）・シークレット発見・シークレット制覇（1ステージ全部）・10ステージクリア・100ステージクリア |

青コインは家具・背景・都道府県ガチャにも使うアプリ共通残高。記録はアカウントごとにサーバーへ保存し、青コイン台帳と同じトランザクションで確定する。端末の旧記録は初回だけ発見・クリア・実績・経験値を引き継ぐ。旧ゲーム専用残高は共通財布へ加算せず、旧localStorageは残す。新しいlocalStorageの控えはアカウント別のキーを使う。
旧キーは `odekake_kakure_kanji_v1`、新しい控えのキーは `odekake_kakure_kanji_blue_v1:<アカウントID>`。

## 5. 新しいステージ（漢字）を足す手順

**問題数をふやすために、確かめていない答えを入れない。** 1問ずつ次のとおりに作る。

1. `data/stage-XXX-<字>.ts` を作る（`stage-001-kan.ts` をまねる）。
2. 出題漢字の筆画を、**日本の筆順どおり**に `strokes` へ描く（viewBox 0 0 100 100、`kind` は画の種類）。
   描いたらブラウザで、教科書体・明朝のフォントと見くらべて形がおかしくないか確かめる。
3. 答えを1字ずつ決める。字源（部品の分け方）と画の形・位置の両方で取り出せる字だけを入れ、`evidence`（根拠）と
   `verification.note`（どう確かめたか）を書く。迷う字は入れないか `pending` にする。
   `grade` は学年別漢字配当表で確かめて書き、`data/grades.ts` にも足す（小学校で習わない字は null＝シークレット）。
4. 似ているけれど答えにならない字を `nearMisses` に、理由と分類（shape／position／missing／radical）つきで書く。
5. 答えと似た字の画の種類を `data/structures.ts` に足す（テストで、答えの筆画の組がその字の画の種類・画数とぴったり合うか、
   似た字の分類が正しいかを照合する）。
6. `data/index.ts` の `ALL_STAGES` に足す。ステージ番号は1から順番。
7. `npm run test:kakure-kanji` を通す。すべての筆画の組み合わせ（13画なら8191通り）をためして、登録した組だけが正解になることも確かめる。
8. ブラウザで最初から最後まで遊ぶ（375×667／390×844／430×932）。

難易度のめやす（**見つける字＝小学校で習う字の数**で決める。シークレットは数えない）：初級 2〜3個／中級 4〜6個／上級 7〜10個／超上級 複雑なつくり／達人 見つけにくい字を含む。

## 7. ステージ2「漢」とステージ3「称」（2026-10-17追加）

「寝」「桜」の代わりに「漢」「称」を追加。元の「感」の番号・ID・保存形式はそのまま。
漢は通常8字、称は通常7字なので上級。シークレットはクリアの条件に含めない。

| 出題 | 通常の答え（クリアに必要） | シークレット |
|---|---|---|
| 漢 | 一・二・三・十・口・人・大・夫 | 汁 |
| 称 | 一・十・千・木・小・丁・下 | 禾・卜 |

- 「漢」の独立した横画は4・9・10・11画目。一は4通り、二は6通り、三は4通り。十は4＋5／4＋6の2通り。
- 「漢」の12画目は口の中から左下まで続く1本の払い。途中で切って「中」にしたり、上の突き出しを消して「天」にしたりしない。下の2本は接するので「人」であって「八」ではない。
- 「漢 → 大」は左払いが横画より上へ突き出し、横画の近くで左右へ分かれる形なので正解とする。森・休・体・困の木から縦画を外した形とは区別する。
- 「漢 → 汁」は左の氵＋右上の十。部品の大きさの比率を問わない見立て。汁は常用漢字だが教育漢字ではないのでシークレット。
- 「称」の7画目は日本の字形の横画（中国簡体字の「尔」の横鉤とは別）。右で7＋8が丁、7＋8＋10が下、8＋9＋10が小。
- 「称 → 下」は縦鉤の小さなはねだけを見立てる。のぎへんの5画目は秋・想と同じ短い点として扱い、点を右払いに変えた八は除外する。「称 → 卜」は縦3画目と点5画目の2画。木・禾は右下が点になる部品字形を用いる。
- 「称 → 禾」は左の部品全体。禾は単独の漢字でもあるが教育漢字ではないためシークレット。
- 字形・筆順の確認資料：[漢](https://kakijun.jp/page/1377200.html)／[称](https://kakijun.jp/page/10173200.html)。筆画SVGはこのアプリ用の独自描画。
- 追加した2問は全筆画の組み合わせ（漢8191通り・称1023通り）、通常クリア→保存→シークレット完成、似た字の誤判定をテストする。

- ステージは24問。まだ問題がない難易度は「準備中」と出している。
- 記録・青コインの確定には通信が必要。通信に失敗したら同じ操作IDで再試行する。
- PWA はアプリ全体の設定のまま（このゲーム専用のオフライン対応はしていない）。

## 12. 共通の青コインとの連携

- `actions.ts` が正解判定・ヒント代・報酬をサーバーの時刻と記録から計算する。ブラウザは操作を送り、コインの増減額は送らない。
- `user_kakure_kanji` にアカウントごとの進行、`kakure_kanji_receipts` に操作IDと確定結果を保存。RLSは本人の読み取りだけを許可。
- `commit_kakure_kanji` は認証IDと専用HMAC署名を確認し、リビジョン一致・青コインの残高確認・台帳記入・記録保存をまとめて行う。署名キーは `kanji_private.wallet_keys` とVercelのサーバー専用 `KAKURE_KANJI_WALLET_SECRET` に保管し、Gitには含めない。production / previewは別の値を使う。
- 再送は同じ操作IDの記録を返し、二重に報酬やヒント代を付けない。別画面から更新されたら最新の記録を読み込み、操作し直せる。
- 「最初から」は挑戦中のラウンドだけを消す。青コイン、クリア・実績、ログイン・経験値を維持し、初回報酬を再発行しない。
