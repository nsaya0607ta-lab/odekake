## 1. できるようになったこと

- おでかけレベルが上がると、到達したレベルに応じたコインがもらえます（1レベル1回だけ）。
- 1日の歩数に応じてコインがもらえます（段階報酬・1日あたり最大70枚）。
- 所持コインがホームの右上に出ます。押すと「おでかけコイン」画面へ移動します。
- 今日の歩数カードに「次に解放（次のレベルアップで自動的に解放される報酬）」「所持コイン」が出ます。

コインは EXP と同じ考え方で、**台帳（`coin_events`）と残高（`user_coins`）に保存**します。
画面を開くたびに数え直さないため、あとから履歴の表示を変えても残高がずれません。

## 2. コインの量

### レベルアップ報酬（到達レベルごとに1回）

| 到達レベル | コイン |
| --- | --- |
| Lv.2〜5 | 100枚 |
| Lv.6〜10 | 150枚 |
| Lv.11〜15 | 200枚 |
| Lv.16〜20 | 250枚 |
| Lv.21〜25 | 300枚 |
| Lv.26〜29 | 400枚 |
| Lv.30 | 1,000枚 |

Lv.30 だけ大きくして、最後までレベルを上げる動機にしています。
Lv.2 から Lv.30 まで全部で 7,500枚です。

### 歩数報酬（1日ごと・最大70枚）

| 1日の歩数 | 獲得コイン | その日の合計 |
| --- | --- | --- |
| 3,000歩 | 10枚 | 10枚 |
| 5,000歩 | ＋10枚 | 20枚 |
| 8,000歩 | ＋15枚 | 35枚 |
| 10,000歩 | ＋15枚 | 50枚 |
| 15,000歩 | ＋20枚 | 70枚 |

毎日10,000歩なら 50枚 × 30日 = 約1,500枚/月です。
同じ日の歩数が増えたときは差分だけ増え、減ったときは減った分だけ戻ります
（レベルアップ分は減りません）。

### レベルアップ報酬にコインは要りません

Lv.2〜30 のレベルアップ報酬（アクションや見た目）は、レベルに到達すれば自動で解放されます。
コインは今のところ**もらうだけ**で、何かを解放するためには使いません
（以前は「解放にいくら必要か」という目安表示がありましたが、紛らわしいため削除しました）。

**付与量は `src/lib/coins.ts` に、同じ値が
`supabase/migrations/0011_odekake_coins.sql` にあります。変えるときは両方を揃えてください。**
（歩数EXPと同じで、アプリ側とデータベース側でズレないようにするためです）

## 3. 画面

### ホーム（`/home`）

- 右上に所持コインのボタンを足しました（押すと `/mypage/coins`）。
- 「今日の歩数」カードに、次のレベルアップで解放されるものの名前・所持コインを足しました。
- 2つのカードの高さを 240px から 272px に広げています（行が増えたため）。
- そのほかのホームの見た目は変えていません。

いただいた画像では「次に**開**放」でしたが、アプリの既存の表記（レベル札・EXP履歴）が
「次に**解**放」なので、そちらに合わせています。

### おでかけコイン（`/mypage/coins`）

ホームのコインボタンから開く画面です。いただいた画像のとおりに並べています。

| 上から順に | 中身 |
| --- | --- |
| ヘッダー | 自分の旅の名前＋「おでかけも、思い出も、いっしょに。」と、右上に所持コイン（「＋」はコインのもらい方へ移動） |
| コインのカード | 「コインを集めて、つかおう！」の帯、所持コイン、今日のボーナス・コインミッションの2つの札、右に**着せ替えプレビューの犬**と宝箱 |
| コインでガチャ / ショップでつかう | 2枚のカード（ボタンは見た目だけ。中身は後述） |
| ショップで買うとこうなる | 3つの見本を横スクロールで。購入前・購入後の絵と値段つき |
| おでかけの記録 | おでかけした場所・訪れたエリア・訪問数 |
| （画像より下） | 次に解放できるもの／コインのもらい方／コインの履歴／解放に必要なコインの一覧 |

- 犬の絵と宝箱・金貨は、着せ替えしたときの見た目を見るプレビュー枠です。
  着せ替えの中身はまだないので、いまは今の姿をそのまま出しています。
- 「ショップで買うとこうなる」の3つ（ふかふかベッド800・おもちゃ箱600・レインコート900）は
  **見本**で、実際の商品ではありません（`src/components/coin-shop-preview.tsx`）。
  購入前・購入後の絵は、手持ちの犬のイラストと図形を組み合わせて作っています。
- ガチャ・ショップ・宝箱・かごなどの絵は素材を持っていないため、
  ホームの草原と同じように図形で描いています（`src/components/coin-art.tsx`）。
- 画像より下には、コインのもらい方と履歴を残しています（コインの中身を確かめられるように）。

マイページのメニューからも開けます。

## 4. データベース

`supabase/migrations/0011_odekake_coins.sql` を足しました。

| 追加したもの | 役割 |
| --- | --- |
| `user_coins` | 残高（`balance`）と獲得合計（`total_earned`） |
| `coin_events` | 台帳。1件ごとに理由と枚数を残す（正が獲得・負が消費） |
| `exp_level_of()` | 合計EXPからレベルを求める（`src/lib/exp.ts` と同じ段階） |
| `coin_level_up_reward()` / `calculate_step_coins()` | 付与量の定義 |
| `add_coin_event()` / `set_coin_event()` | 台帳への書き込み（内部用。APIからは呼べません） |
| `sync_level_up_coins()` ＋ `user_exp` のトリガー | EXPが増えてレベルが上がったときにコインを配る |
| `record_daily_steps_for_user()` の差し替え | 歩数の同期時にコインも同期する |

- どちらのテーブルも本人しか読めません（RLS）。書き込みは `authenticated` に許可しておらず、
  SECURITY DEFINER の関数だけが行います。台帳へ直接コインを足すことはできません。
- 既存の利用者の分（今のレベルまでの報酬と、記録済みの歩数分）は
  マイグレーションの中でまとめて配ります。
- 何度適用しても増えません（付与キーで重複を防ぎ、最後に台帳の合計で残高を揃えます）。

## 5. 今回入れていないもの

**コインを使う機能（ガチャ・ショップ・着せ替え）はまだありません。**
ご指示のとおり、カード（見た目）だけを置いています。具体的には次のとおりです。

| 見た目だけのもの | いまの動き |
| --- | --- |
| 「ガチャをまわす」「ショップへ行く」のボタン | 押せません（`disabled`） |
| 「ショップで買うとこうなる」の3つの見本 | 商品ではありません。値段も仮 |
| 「もっと見る」と見出しの「？」 | 行き先はありません（飾り） |
| 「コインミッション 達成でGET！」の札 | ミッションの仕組みはまだありません |
| 着せ替えプレビューの犬 | 着せ替えの中身がないため、今の姿のまま |

報酬の解放は今までどおりレベルで決まり、コインは要りません。

作るときのために、台帳は負の値を持てるようにし、`event_type` に `'unlock'` を用意しています。
消費の関数と「解放済み」の記録を足せば、残高の計算はそのまま使えます。

「今日のボーナス」は実際の値で、今日の歩数でもらえるコインを出しています
（ログインボーナスの仕組みはまだないため）。

## 6. ついでに直したもの

コインの作業中に見つかった、コインとは別の不具合を2つ直しています。

1. **EXPを持っている利用者がアカウントを削除できなかった**
   退会すると `exp_events` が連鎖削除されますが、そのトリガーが消えたユーザーの
   `user_exp` を作り直そうとして外部キー違反になり、削除そのものが失敗していました。
   削除のときは残っている残高を更新するだけに変えました（`sync_user_exp_total()`）。
   コインの残高トリガーも同じ作りにしています。

2. **RLSテストの歩数の項目が日付固定で、時間が経つと必ず失敗していた**
   歩数RPCは8日以上前の日付を受け付けないため、`2026-01-12` 固定だと期限切れになります。
   「日本時間の今日」を使うように変えました。

## 7. 適用の手順

1. Supabase の SQL Editor で `supabase/migrations/0011_odekake_coins.sql` を実行します
   （`supabase db push` でも構いません）。
2. アプリをデプロイします。

先に SQL を当ててください。アプリ側は `user_coins` が読めないときは 0枚として表示するため、
順序が逆になってもホームは落ちませんが、コインは 0 のままになります。

## 8. 確認したこと

```bash
npm run typecheck    # 通過
npm run lint         # 通過
npm run build        # 通過
./scripts/verify-rls.sh   # 105項目すべて成功
```

`supabase/tests/01_rls.test.sql` に、コインの項目を足しました。

- レベルアップ報酬が到達レベルごとに1回だけ入る（Lv.7 までで 700枚）
- 歩数報酬が1日1行で最大70枚になる
- 残高が台帳の合計と一致する
- 歩数が減ると歩数コインも減り、レベル分は残る
- 他人の残高・台帳が見えない
- 台帳へ直接コインを足せない・残高を直接書き換えられない
- 退会でコインの台帳と残高も消える

Supabase プロジェクトに接続した状態での確認は行っていません
（この作業環境から接続できるプロジェクトがないため）。
画面の見た目は、ローカルの開発サーバーで実際に描画して確かめています。
