# 実装メモ・仕様の補足

仕様書（版数 1.0）に対する実装上の判断と、現時点の制限事項をまとめています。

## 仕様書からの補足・変更点

### テーブル定義に追加した列

`visit_records` に、仕様書の入力項目を保存するための列を追加しています。

| 列 | 対応する入力項目 | 追加理由 |
| --- | --- | --- |
| `companions` | 一緒に行った人 | 仕様書16章の入力項目にあるが、20章のテーブル定義に列がなかったため |
| `note` | メモ | 「感想」を `comment`、「メモ」を `note` として分けて保存するため |

### `profiles` の主キー

仕様書では `id` と `user_id` の両方が挙げられているため、`id` を独立した主キー、
`user_id` を `auth.users` への一意な外部キーとしています。アプリ側の検索は `user_id` で行います。

### スポットの評価・お気に入り・訪問回数

`spots` テーブルには評価やお気に入りの列を持たせず、紐づく `visit_records` から集計しています。

- 評価 = 訪問履歴の評価の平均
- お気に入り = いずれかの訪問履歴でお気に入りが付いている
- 訪問回数・最終訪問日 = 訪問履歴の件数と最新日

同じスポットへの再訪問はスポットを重複登録せず、訪問履歴を追加する形になります（仕様書15章）。

### スポットの代表写真

`spots` に写真用の列はないため、最後に訪れた訪問履歴の1枚目を代表写真として表示しています。

### 緯度・経度

スポット登録時に市区町村を選ぶと、その市区町村の代表座標を `latitude` / `longitude` に保存します。
市区町村詳細の「地図表示」はこの座標を使った簡易的な配置図です。番地単位の測位は行いません。

## 制限事項

### 招待メールは送信しません

共有旅の招待は `trip_invitations` にレコードを作成し、招待コードと招待リンクを共有する方式です。
メール送信自体は行いません（Supabase の招待 API はサービスロールキーが必要で、
仕様書29章の「秘密鍵をクライアントコードへ記載しない」方針と、鍵を持たない構成を優先しました）。

招待されたユーザーは、ログイン後に以下のいずれかで参加できます。

- マイページ →「共有旅の招待」で、自分のメールアドレス宛の招待を確認して参加
- 受け取った招待コードを入力して参加
- 招待リンク `/join/{code}` を開いて参加

未登録ユーザーへの招待は、`trip_invitations.email` にレコードが残るため、
登録後に同じメールアドレスでログインすれば招待を確認できます。
将来メール送信を追加する場合も、この構造のまま拡張できます。

### 市区町村の地図表示

都道府県詳細の市区町村選択は、地図ではなく検索付きの一覧です（北海道は179件あるため、
一覧と検索のほうが操作しやすいと判断しました）。地方地図と都道府県の選択は地図から行えます。

### 沖縄県・離島

日本地図では沖縄県を左上へ移動して表示しています。また、表示の簡素化のため
先島諸島（宮古・八重山）と小笠原諸島は描画を省いています。
これらの市区町村は一覧・検索・記録では通常どおり扱えます。

### 写真の孤立ファイル

写真は保存ボタンを押す前に Storage へアップロードします。フォームを保存せずに画面を離れると、
Storage 上にファイルが残る場合があります（アプリからは参照されません）。
定期的なクリーンアップ処理は未実装です。

### 訪問回数による色分け

地図の塗り分けは「未訪問 / 訪問済み」の2段階です。`loadAreaIndex()` が地域ごとの
`visitCount` を返しているため、色の段階を増やす拡張は `AreaMap` の色指定だけで行えます。

### viewer ロール

`trip_role` 列挙型と権限判定には `viewer` を用意していますが、画面から付与する導線はありません。
追加する場合は、`visit_records` の insert ポリシーで `viewer` を除外する条件を足すことになります。

## 動作確認について

Supabase プロジェクトに接続した状態での実行確認は行っていません
（この作業環境から接続できる Supabase プロジェクトがないため）。
型チェック・ESLint・本番ビルドは通っています。UI は各画面のコンポーネントを
モックデータで描画してスマートフォン幅で確認しています。

接続後に最初に確認すべき点

1. サインアップ → 確認メール → ログインの一連の流れ
2. 一人旅の記録が、共有旅のメンバーから見えないこと
3. 共有旅に参加していないユーザーが `/trips/{id}` を開けないこと
4. 写真のアップロードと、署名付き URL での表示
5. アカウント削除（`delete_own_account()`）
