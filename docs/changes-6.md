## 1. 背景

`src/lib/exp.ts` の `LEVEL_REWARDS` には、Lv.2〜30 の報酬名がレベルアップ時から
ずっと定義されていました（例: Lv.4「若葉の首輪」、Lv.6「お花のバンダナ」）。
名前は EXP履歴画面（`/mypage/exp-history`）の一覧に出ていましたが、それを見返す場所や、
実際に「装着する」という操作がどこにもありませんでした。今回、この2つを追加しています。

## 2. できるようになったこと

- レベルアップ報酬のうち、身につけるもの（アクセサリー・称号）を一覧で見返せます。
- 解放済みのアクセサリー・称号を、スロットごとに1つだけ選んで装着・解除できます。
- 装着中のものは、そうび画面のプレビューでアイコンとして確認できます。
- モーション・表情・お部屋の報酬（装着の概念がないもの）も、まとめて一覧で見返せます。

マイページのメニュー、または EXP履歴画面から「そうび」（`/mypage/gear`）へ入れます。

## 3. 画面

### そうび（`/mypage/gear`）

上から次の順に並んでいます。

| セクション | 内容 |
| --- | --- |
| そうびプレビュー | 犬の絵に、装着中のアクセサリーをアイコンで重ねて表示。称号があれば名前も表示 |
| アクセサリー | 首輪・バンダナ・帽子・リュック・クラウンの5スロット。スロットごとに解放済みの選択肢がチップで並び、タップで装着／解除 |
| 称号 | 解放済みの称号をチップで並べ、タップで選択（同時に1つ） |
| しぐさ・表情 | 一覧のみ（自動で使われるため装着不要と明記） |
| おへや | 一覧のみ（将来のお部屋づくり機能向けと明記） |

未解放の選択肢は鍵アイコンと「Lv.Xで解放」の表示になり、タップできません。

### EXP履歴（`/mypage/exp-history`）

「そうび」への案内カードを1枚追加しました。既存の内容（レベル・EXP履歴・解放報酬一覧）は
変えていません。

## 4. データベース

`supabase/migrations/0012_user_equipment.sql` を追加しました。

| 追加したもの | 役割 |
| --- | --- |
| `user_equipment` | 装着中の状態（`user_id`, `slot`, `level`）。1ユーザー1スロットにつき1行 |
| `equipment_slot_of(level)` | 到達レベルの報酬がどのスロットに属すかを返す |
| `set_equipped_item(slot, level)` | 装着・解除の唯一の入口（SECURITY DEFINER）。解放前のレベルやスロット不一致は拒否する |
| `user_exp` への追加トリガー | EXPが減ってレベルが下がった場合、条件を下回った装着中アイテムを自動で外す（保険） |

- `user_equipment` は本人しか読めません（RLS）。書き込みは `authenticated` に許可しておらず、
  `set_equipped_item()` だけが行います。テーブルへの直接 `insert` はできません。
- スロットとレベルの対応（`src/lib/equipment.ts` の `SLOT_BY_LEVEL` と
  `equipment_slot_of()`）は両方に書いてあります。**アクセサリー・称号のレベルを変えるときは
  両方を揃えてください。**

## 5. 見た目に反映されないもの（重要な制限）

**犬の絵そのものは着せ替えできません。** ホーム画面を歩き回るフレブルや、各ポーズの絵
（`public/characters/frenchie/*.webp`）はどれも固定の1枚絵で、首輪やバンダナを描き分けた
差し替え用の素材を持っていません。そのため：

- 装着中のアクセサリーは、**そうび画面のプレビューにアイコンとして重ねて表示するだけ**です。
  ホーム画面のフレブルや、ほかの画面の見た目は変わりません。
- アイコンは新しく描いた簡易的なもので、実際の商品画像ではありません（`src/components/gear-art.tsx`）。

犬の絵を実際に着せ替えるには、アクセサリーごとの差分素材（またはレイヤー分けした素材）を
新たに用意する必要があります。台帳（`user_equipment`）はそのまま使えるので、素材が揃った
段階で反映先を追加すれば動きます。

称号（`title`）は文言なので実際に反映できており、そうびプレビューと画面内の表示に出ます。
モーション・表情は装着の概念がなく、解放済みならおさんぽ中に自動で使われます（これは
以前からの仕様のままです）。

## 6. 適用の手順

1. Supabase の SQL Editor で `supabase/migrations/0012_user_equipment.sql` を実行します
   （`supabase db push` でも構いません）。
2. アプリをデプロイします。

先に SQL を当ててください。`user_equipment` が読めない間は「まだ何も装着していません」
という表示になるだけで、そうび画面自体は開けます。

## 7. 確認したこと

```bash
npm run typecheck    # 通過
npm run lint         # 通過
npm run build        # 通過
./scripts/verify-rls.sh   # 118項目すべて成功
```

`supabase/tests/01_rls.test.sql` に、そうびの項目を足しました。

- 解放済みのアクセサリーは装着できる
- まだ解放していないレベルの称号は装着できない
- レベルとスロットが一致しないものは装着できない（例: Lv.4の首輪をバンダナ枠へ）
- 装着中のスロットへの付け替えは1スロット1件のまま保たれる
- 解除すると行が消える
- 他人のそうびは見えない
- RPCを介さず直接テーブルへ装着できない
- 退会でそうびの記録も消える

画面の見た目と、装着・解除の操作は、ローカルの開発サーバーで実際に描画して確認しています
（画面上の全アクセサリー・称号・鍵表示・プレビューのアイコン重ね位置を含む）。
Supabase プロジェクトに接続した状態での確認は行っていません
（この作業環境から接続できるプロジェクトがないため）。
