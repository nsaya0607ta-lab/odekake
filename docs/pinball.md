# ご当地ピンボール（ミニゲーム05）設計メモ

都道府県ガチャで集めたご当地アイテムが台に並ぶ、本格的なピンボール。3球制・真上から見た2D。
台は形のちがう**マップ**から選ぶ（いつもの台・はねはね台・くぎと風車の台・ジェットコースター台。下の「マップ」）。
マップごとに形と色・模様・曲がちがい、どのマップもだれでも遊べる。持っているご当地アイテムは、どの県のものも全部、どのマップにも出る。
はじめは「県ごとの台」（形は1つで、県ごとに色・曲を着せ替え）だったが、2026-10-08 にマップごとに作りなおした（記録の扱いは「赤コインと記録」）。
スコアで**赤コイン**がもらえる。赤コインで部品を買うと、台の上のほうを自分で作った**ステージ**を作れて、フレンドに公開すると
おたがいに遊べる（下の「ステージ」）。コインは「赤（0134）→ 使い道が無いので青（0136）→ 部品が買えるようにして赤（0138）」と変わってきた。
ガチャでたくさん集めるほど強くなる：ご当地アイテム（全部の県）の種類で「図鑑ボーナス」、同じアイテムの数でスキルLv（Lv5で「覚醒」、
そのあとは限界突破の★）。下の「ガチャで集めるほど強くなる」。

## マップ（maps.ts・themes.ts）

台えらびには、形のちがうマップが並ぶ（だれでも全部遊べる）。名前・色・曲は themes.ts、形は maps.ts（同じ id）。

| id | 名前 | しかけ | ランプをのぼった玉 | むずかしさ |
| --- | --- | --- | --- | --- |
| `default` | いつもの台 | バンパー3つ・かざぐるま1つ（前の県の台と同じ形） | 同じがわのインレーンへ（左右交互で「8の字」） | ★ |
| `bumper` | はねはね台 | 上のまん中にバンパー4つ＋左右の細いスリングショットでかこった「はねはね部屋」、その出口の左右にバンパー2つ（バンパー6つ）。バンパーは 1.15 倍の強さではじく | ワイヤーで上へ運ばれて、部屋の上から飛びこむ | ★★ |
| `pachinko` | くぎと風車の台 | しんちゅうのくぎ（正三角形のこうし・38mm おき）・風車2つ・バンパー2つ。**ガチャ穴のかこいの上があいていて**（40mm）、上から落ちてきた玉も入る（パチンコのまん中の入賞口） | ワイヤーで上のまん中へ運ばれて、くぎの間を落ちてくる | ★★ |
| `coaster` | ジェットコースター台 | 左右のランプがまん中で X に交わる長いランプ。左右のバンパー2つ・かざぐるま1つ | ななめに台を横切って、**反対がわ**のインレーンへ（同じショットをくり返しねらえる） | ★★★ |

- **骨組みはどのマップも同じ**：外わく・打ち出しレーン・上のレーン・オービット（スピナー）・ランプの入口（ここからのぼり坂）・
  ガチャ穴とドロップターゲット・スリングショット・インレーン／アウトレーン・キックバック・フリッパー。
  だから大きなショット5つの狙い方（フリッパーのどこで打つとどこへ行くか）と打ち出しの強さは、どのマップでも同じ
  （`shotmap`・`plunger` の結果は、まん中へまっすぐ上がる玉が上の部品に当たるところ以外は同じ）。ルール・得点・スキルも同じ。
- マップごとに変わるのは `MapSpec`（table.ts）：バンパー・かざぐるま（何個でも）・足すポスト／くぎ・壁・上のスリングショット・
  スタンドアップターゲットの位置・アイテムが浮かぶ場所・ランプの道（`ramp`・左右で変えるときは `rampRight`）・
  ランプの落とし方（`exitSpread`）・バンパーの強さ（`bumperKick`）・ガチャ穴の上をあける幅（`scoopTopOpening`）。
- 作るときにわかったこと（新しいマップを作るときも同じ）：
  - **上半分には、あまり玉が来ない**（いつもの台で、玉がいる時間の約2割）。上に部品を並べるだけでは当たらない
    （バンパー6つを上に並べただけでは、当たりはいつもの台の約1.4倍だった）。上を主役にするマップは、ランプで玉を上へ運ぶ。
  - **台の上へ落とすランプは、落とす向きと速さをばらつかせる**（`exitSpread`：向き ±15〜18°・速さ ±15%）。いつも同じ所・同じ向きに
    落とすと、その先の玉の行き先が毎回ほとんど同じになり、落とす場所を 1mm 動かしただけでコインの平均が 114〜197枚までゆれた。
  - **動かない部品どうしのすき間は「玉が通る 31mm 以上」か「通さない 14mm 以下」を目安に**（玉の直径は 27mm）。
    そのあいだ（とくに上を向いた V の形）には玉がのって止まる。はねはね台のスリングショットを外へ 3mm 太くしただけで、
    スタンドアップターゲットとの間に 600ゲームで数百回止まった（いまはそこを 28〜30mm にして、stuck で止まらないのを確かめてある）。
    バンパーのように玉をはじく部品とのすき間は、せまくても止まらない。
    くぎは、風車の羽根がとどく円から 31mm 以上はなす。くぎのはね返りはゴムのポストと同じ（金属だと勢いがなくなって、くぎの上にのりやすい）。
  - `node scripts/simulate-pinball.mjs gaps <マップ>` で、動かない部品どうしの 14〜31mm のすき間（いつもの台にもある骨組みのぶんはのぞく）が出る。
    ここに出たところは `stuck` で止まらないかを必ず確かめる（いまは、はねはね台のスリングショットとターゲットの間の 28〜30mm だけで、確かめてある）。
- バランス（下の「バランス」）：ふつうの腕前の赤コインが、どのマップもいつもの台の ±10% に入るようにしてある。
  はねはね台は運の要素が大きく、初心者はいつもの台より少し稼ぎやすく、上手な人は少し稼ぎにくい。
  くぎと風車の台は玉が上でゆっくり落ちてくるぶん、1プレイが少し長い。

## 台（table.ts）

- 大きさは 522 × 1000 mm（本物の台の比率）。玉の半径 13.5 mm、重力 1180 mm/s²（台の傾き約7°）。
  スマホでは本物の速さだと目で追いにくいので、台の上の時間を `GAME_SPEED`（0.75）倍で進める（下の「玉の速さ」）。
- 骨組み（どのマップも同じ）は上から：外まわりのアーチ → 上のレーン「お・で・か・け」（4本） → （マップごとの部品） →
  左右のランプ（坂）とまんなかのガチャ穴（キックアウトホール） → ドロップターゲット3つ（ガチャ穴の前をふさぐ） →
  左右のオービット（外まわり） → スリングショット → インレーン／アウトレーン → フリッパー2本 → 右の打ち出しレーン。
  左右の上のすみのスタンドアップターゲット（3つずつ）も全部のマップにある（位置はマップで少し変えてよい）。
- 台は `buildTable(spec)` で組み立てる。壁とポストの順番は当たり判定の順番になるので、骨組みの順番は変えない
  （変えると、いつもの台の結果まで少し変わる）。マップの部品は骨組みのあとに足す。
- スタンドアップターゲットは、反対がわのフリッパーから、ガチャ穴の横の通り道とランプの下をぬけた玉が当たる向きに立てる。
  前の面（`face`）に当たったときだけ光る。後ろは両はしの丸い1本の台（ポストを別に置くと、つなぎ目のくぼみに玉が乗る）。
- 大きなショットは5つ（`SHOT_IDS`）：左オービット・左ランプ・ガチャ穴・右ランプ・右オービット。
  ランプの入口はどのマップも同じで、のぼった先（ランプの道）がマップごとにちがう。
- アイテムが浮かぶ場所は10か所（`itemSpots`）。tier 0＝マップの上半分の部品のあたり（取りやすい）、1＝ガチャ穴・ランプの手前、
  2＝ランプやオービットの入口（狙わないと取れない）。tier 1・2 の7か所はどのマップも同じ。レア度が高いほど tier 2 に出やすい（game.ts `TIER_WEIGHT`）。
  `shot` は、そのショットで通る場所（シミュレーターのボットが狙うのに使う）。
- 形を変えたら必ず `node scripts/simulate-pinball.mjs shotmap <マップ>` と `plunger <マップ>` で、
  フリッパーのどこで打つとどこへ行くか・打ち出しの強さごとの行き先を確かめる。
  打ち出しの強さが変わったら、`config.ts` の `SKILL_SHOT_POWER`（打ち出しゲージの目印）も合わせる。
- あわせて `node scripts/simulate-pinball.mjs stuck 600 <マップ>` で、玉が止まってしまう場所が出ないことを確かめる
  （0.5秒以上止まった場所を数える。2.3秒以上の「長く止まった」が 0 で、短いものも数回だけにする）。
  **平らな上の面は作らない**：台はななめなので、上を向いた水平の面（箱のふた・ターゲットの上など）に玉が乗ると止まる。
  ランプの入口の箱のふたは山形、ガチャ穴のかこいの頭はとがったアーチにしてある（上をあけるマップは、アーチを左右で切る）。

## 描画（render.ts・materials.ts）

- 光は左上から当たる決まり。つやの筋は左上、影は右下に落とす。材質ごとに描き分ける：
  レール・ガイド・ワイヤー＝めっきの丸い棒（`chromeTube`）、ポスト＝白いゴムの輪＋ねじ頭、
  スリングショット＝ゴムの上に色つきプラスチックのカバー（テーマの accent）と肉球の絵、
  バンパー＝プラスチックの台座（accent2）・めっきのリング・光る胴・アイテムの絵の笠（ドームのつや）、
  ランプ＝透明なプラスチックの床と壁（テーマの plastic）＋頂上からのワイヤーランプ、床のランプ＝色つき樹脂（消えていても色が見える）。
- 描くのはゲームと同じ台の形（`RenderAssets.table`）。バンパー・スリングショット・かざぐるまの数はマップごとにちがうので、
  光らせる配列は台の形から作る。バンパーの笠の絵は、持っているアイテムのレア度の高い順（バンパーが多いマップは足りないぶんを ？カプセル）。
  くぎ（`look: "peg"`）はしんちゅうの丸い頭と小さな影。上をあけたガチャ穴のかこいは、左右2本の壁として描く。
  自分で作るステージの部品：ガイドレール＝めっきの丸い棒（`look: "guide"`）、ゴムのかべ＝白いゴム（`look: "rubber"`。両はしにポストの頭）、
  ブロック＝色つきの透明プラスチック（`look: "block"`。accent2・中に電球の光と肉球。当たり判定の形のとおり、中心線のひし形を r だけ太らせて描く）、
  回転バー＝2本羽根のかざぐるま、スピナー＝両はしの金具（base）と回る板（毎フレーム。**下をくぐる玉より上に描く**）、
  ドロップターゲット＝ガチャ穴の前のものと同じ絵を、置いた向きに回して描く（たおれたら床と同じ高さの頭だけ）。
- 層は3つ。**base**（床・模様・県の形・床のランプ・レール・ポスト・スリングショット・バンパーの台座・ランプとワイヤーの影）と
  **overlay**（ランプ・ワイヤー・エプロン）は、大きさが変わったときに一度だけ描く。影のぼかし（shadowBlur）はこの2つの中でだけ使う。
  毎フレームは、光るランプ・バンパーの上半分（前もって作った絵）・動く部品（ドロップターゲット・スピナー・キックバック・
  スリングショットのはじく面・フリッパー）・玉・アイテム・演出だけを重ねる。
- 重なり順：床の玉 → overlay（ランプ・ワイヤー） → 浮かんでいるアイテム → ランプの上の玉。
  ランプの入口（y ≧ 576）は玉がまだ床を転がっているので base に描き、それより上を overlay に描く（同じ描き方でつなぎ目を消す）。
- 見た目の太さは当たり判定に合わせる（例：スリングショットのはじく面 8mm、ほかの辺 6mm、ドロップターゲット 7mm、
  かざぐるまの羽根 9mm、スタンドアップターゲット 5mm、くぎ 7mm）。かざぐるまは前もって描いた羽根の絵を回して描き、速いときは残像。
  台の形（table.ts・maps.ts）を変えたら、描画も合わせて確かめること（ランプのワイヤーがバンパーや風車の上を通らないようにする）。
- 重さの目安（ヘッドレスの Chrome・390×700・dpr 2）：base 約10ms・overlay 約6ms（作りなおすときだけ）。
  毎フレームの描画は、スマホの大きさ（390×844・dpr 2）で 60fps のまま（フレームの間かく 95% が 16.8ms 以内）。
- 見せる範囲は `RenderAssets.view`（mm。無ければ台の全体）。ステージのエディターは台の上のほう（`EDITOR_VIEW`）だけを大きく描き、
  上に重ねる SVG の viewBox を `visibleRect()` にそろえる（SVG の座標＝台の座標になるので、タップした位置も SVG から台の座標にできる）。

## 物理（physics.ts）

- 1ミリ秒ごとの固定ステップ。速い玉が壁をすりぬけないよう、1ステップの移動が玉の半径より小さくなるようにしてある。
- 壁はすべて「太さのある線」（カプセル）。格子（40 mm）で近くの壁だけを調べる。
- 材質ごとに反発と摩擦（metal / plastic / rubber / post）。速いほど反発が小さくなる。
- フリッパーは太さが変わる棒。振っている間は面の速さ（角速度×支点からの距離）で玉を運ぶ（`flipperSwing`）。
  上げたまま待てば玉を止められる（キャッチ）ので、止めてから狙って打てる。
- 当たり判定の下調べ（格子に入れた壁・ポスト）は、台の形ごとに一度だけ作る（`createWorld(seed, table)`）。
- バンパー・スリングは当たると蹴り返す（スリングは面の中だけ。角は蹴らない）。バンパーの強さはマップの `bumperKick` 倍。
- ランプは道に沿って進む（のぼりきれないと戻る）。ゲートは片側だけ通す。スピナーは通った速さで回る。
- 自分で作るステージのスピナー（`table.spinners`）は当たらない板。玉の中心が板の線を横切ったら `spin` を知らせる
  （同じ玉・同じスピナーは 0.12秒に1回）。ドロップターゲット（`table.stageDrops`）はガチャ穴の前のものと同じ当たり方
  （110mm/s より速く当てるとたおれて、当たらなくなる。`stageDropsUp`）。どちらもマップには無いので、マップの結果は1文字も変わらない
  （`node scripts/simulate-pinball.mjs 40 average 8 all` で、足す前と出力が同じことを確かめた）。
  台の上へ玉を落とすランプ（`exitSpread` があるもの）は、落とす向きを ±exitSpread、速さを ±15% ばらつかせる（乱数は台の乱数）。
- かざぐるまは羽根4本の回る棒（マップによって 0〜いくつか。ふだんの回る速さと向きはかざぐるまごと。いつもの台は時計まわりに 2.6 rad/s）。
  当たった場所の速さ（ω × r）を玉に渡し、玉が押した向きに羽根も回る（強く当てると速く回り、1.6秒ほどでふだんの速さに戻る）。
  **羽根の上に乗っているだけの玉（当たりの速さ 70mm/s 以下）では、羽根をおし返さない**。おし返すと、上に何もないかざぐるまに
  ゆっくり落ちた玉が2本の羽根のあいだに乗ったまま、玉の重さで羽根がほとんど止まり、2秒以上動かなくなった
  （でたらめなステージ 150こ × 20ゲームで2回。直したあと 300こ × 20ゲームで 0回。マップのかざぐるまは上にレーンやくぎがあるので起きていなかった）。
- スキル「ふさぐ」の光の扉は、上に乗った玉を上へはね上げる（オービットを少しのぼり、ガイドからインレーンへ戻る）。
- スキル「マグネット」（`world.magnet`・`MAGNET`）：ガチャ穴の前（x 125〜355・y 464〜760）を**上へ動いている**玉だけを、
  穴の口のまん中へ寄せる。かこいの中では穴まで上がりきれるように持ち上げる。止まった玉・落ちてくる玉は引かない
  （引きつづけると、その場で止まってしまう。穴から出てきた玉も下へ動いているので、すぐ戻らない）。穴に玉が入っているあいだは効かない。
  効いているあいだは穴の前のターゲットを倒したままにする（立っていると吸い寄せても入れない）。
  ずっと点けたままの試し（`magnet` で120ゲーム）で、ガチャ穴に入る回数は1分あたり 1.44 → 5.45 回、止まる玉は増えない。
- こすれ（摩擦）は、はね返るような当たりにだけ効かせる。押しつけられているだけの遅い当たりにも効かせると
  「すべり止め」になり、ポストやアーチのてっぺんで玉が止まる。ころがり抵抗も、ほとんど止まっている玉には効かせない。
- 動かなくなった玉（2.5秒）はそっと押す。ガチャ穴に入った玉は時間がたつと打ち出す。
  ガチャ穴の中・かこいの中・すぐ下に玉がいるあいだは、ドロップターゲットを立てなおさない（中の玉が閉じこめられる）。

## ルール（game.ts・config.ts）

- 3球。打ち出してから8秒はボールセーブ。左のキックバックは毎球点いた状態で始まる。
- 秒数（ボールセーブ・コンボ・スキル・アイテムの移動）はすべて実際の秒（`g.clock`）。玉の動きにかかる時間で
  決まる判定（オービットを1周したか・キックバックの直後か）だけは、台の上の時間（`g.world.time`）で見る。
- スキルショット：打ち出しで光っているレーンに入ると 75,000 点（光る場所は打ち出す前にフリッパーで動かせる）。
- 上のレーン4つでボーナス倍率+1（最大×6）。ドロップターゲット全部でガチャ穴が開き、キックバックが点く。
- コンボ：オービット・ランプ・ガチャ穴を4秒以内に続けると ×2〜×5。
- スタンプ帳は8つ（`g.book`）。台に出るのは、持っているご当地アイテム**全部**（どの県のものも。`g.candidates`）で、
  このゲームでまだ出ていないもの（`g.shown`）が先。どれでも8つ取るとスタンプ帳がうまる。持っているのが8種類より少ないと、
  足りないぶんは？カプセル。台に同時に浮かぶのは1つ（ガチャ穴の「よぶ」やスキルで増える。`g.lit`）。
  20秒取られないと別の場所へうつり、そのときまだ出ていないアイテムがあれば、そのアイテムに入れかわる
  （入れかわるのはまだ出ていないものだけ。何にでも入れかわると、むずかしい場所のレアなものを飛ばせてしまい、取りやすくなりすぎる）。
  当てると得点（レア度ごと・×(1＋制覇回数)・★1つで+5%）＋その場でスキル発動。
- スタンプが8つそろうと制覇（大きな文字はマップごとの `conquestTitle`。前は「〇〇県 制覇！」）：500,000 × 制覇回数、ボール+2（3球のマルチボール）、左右のランプとオービットがジャックポット
  （250,000 × 制覇回数）、4つ決めるとガチャ穴がスーパージャックポット（1,000,000 × 制覇回数）。
  ボールが1つに戻ると終わり、新しいスタンプ帳になる。
- すべての得点（ボールが終わったときのボーナスも）に、図鑑ボーナス（`g.zukan`）をかける。
- ガチャ穴のごほうびは重みつきで1つ（`GACHA_AWARDS`）：5万点・10万点・セーブ10秒・キックバック・ボーナス倍率・
  アイテムをよぶ・スタンプ1つ・エクストラボール（1ゲーム2つまで）。
- スタンドアップターゲット：前から当てると光って 3,000 点。3つ全部光らせると 30,000 点＋アイテムをもう1か所よぶ
  （よべないときは 60,000 点）。かざぐるま：当たるたびに 500 点。
- 自分で作るステージの部品：回転バー＝かざぐるまと同じ 500 点。スピナー＝オービットのスピナーと同じ数え方
  （くぐった速さ ÷ 220 回（1〜24回）× 150 点）。ドロップターゲット＝1つたおすごとに 1,000 点、ステージのターゲットを全部たおすと
  3,000 × ターゲットの数のボーナス（2つ以上なら「ターゲット コンプリート！」）。1.2秒後に立ちなおる（ターゲットに重なっている玉がいるあいだは待つ）。
  ガイドレール・ゴムのかべ・ブロックは点にならない（玉の通り道を作る部品）。
- ボールが終わるとボーナス：（アイテム×10,000＋ランプ×5,000＋オービット×4,000＋バンパー×100＋ターゲット×1,000）× ボーナス倍率。

## スキル（skills.ts）

- スキルがあるのは R 以上。Lv は図鑑と同じ（`getSkillLevel`、同じアイテムの所持数）。N と？カプセルは得点だけ。
- 種類：セーブ・得点2倍・3倍・バンパー5倍・スロー・ふさぐ（アウトレーンにフタ）・キックバック・ボーナス倍率・
  ターゲット全倒し・アイテムをよぶ・コンボ受付・まもり（ふさぐ＋セーブ）・マルチボール・フィーバー・得点・奥義（LR）・
  マグネット・スタンプ2倍・おかわり・ジャックポット予約。
  - マグネット：ガチャ穴を開けて、前を通る玉を吸い寄せる（上の「物理」）。
  - スタンプ2倍：その間に取ったアイテムは、スタンプが2つ進む（同じアイテムが2つ入る）。
  - おかわり：このゲームで取ったアイテム（新しい順・スキルのあるものが先。おかわりのスキルのものはのぞく）を、台にもう一度出す。
    取るとスキルがもう一度（おかわりからおかわりは起きない）、得点は半分（`ENCORE_POINTS`）、スタンプは増えない。30秒で消える。
    出せるものが無いときは 30,000 点。制覇モードの間は待って、終わってから出てくる。
  - ジャックポット予約：次のランプ1回がジャックポット（Lv の点 × (1＋制覇回数)。`g.reserves`）。使うまで残る。
- 新しい4つのスキルは、6県で14のアイテムに付けた（岐阜は4つとも。`RECIPES`）。
- 秒数は `LV` の表 × レア度の係数（`RARITY_TIME`：R 1 / SR 1.15 / SSR 1.3 / UR 1.45 / LR 1.6）× ★。
- 得点倍率は重なるとかけ算、上限 ×6（`MAX_SCORE_MULT`）。
- アイテムごとの名前と種類は `RECIPES`。無いアイテムはレア度で自動（R＝セーブ、SR＝2倍、SSR＝まもり、UR＝マルチボール、LR＝奥義）。

## ガチャで集めるほど強くなる（図鑑ボーナス・覚醒・★）

- **図鑑ボーナス**（`zukanBonus`）：台に出るご当地アイテム（全部の県・犬のすがたはのぞく。いまは68種）を何種類持っているかで、すべての得点に
  1 ＋ 0.1 × 持っている割合（全部で ×1.10。`ZUKAN_BONUS_MAX`）。どのマップも同じ。台えらび・遊ぶ画面の上・ルールのページに出る。
  前は「その県の台に出るアイテムのうち何種類か」だった（県の台をやめたので、全部の県まとめてにした。ひとつの県を集めきった人は、
  ×1.10 → ×1.03 になった）。**アイテムを足すと、いま持っている人の割合が下がる**（68種中10種 → 69種中10種）ので、足したときはそのつもりで。
- **Lv5 で覚醒**：Lv5 の数字は Lv4 と同じにして、そのかわり効果をひとつ足す（`build`）。足すのは得点がのびるもの
  （ボーナス倍率+1・アイテムをもう1か所よぶ・スタンプ2倍・マグネット）。キックバックは「＋セーブ」、マルチボールは「ボール+2」、
  おかわりは「2つ」（もとからあった Lv5 の強さ）。
  キックバックやセーブ（玉が長く残る効果）を足すと、1プレイが長くなって得点がふくらみすぎる。シミュレーターで、
  玉が残る覚醒＋ジャックポット予約2回のままだと、全部そろえて Lv5 の人が今の 1.41 倍、★5 で 1.78 倍になった（県の台のころ）。
- **限界突破の★**（`starsForCount`）：スキルLvが MAX になる数（図鑑の決まり）をこえて引いたぶん、1つごとに★1つ（最大★5）。

  県の台のころ（ひとつの県の18種）にこの目標で決めた。マップごとにして全部の県のアイテムが1つの台に出るようになったので、
  **全部の県（68種）をそろえて育てきった人は 1.8 倍くらい**になる（強いスキルのアイテムが台に多く出るのと、図鑑ボーナス ×1.10）。
  ひとつの県のぶん（18種）を育てきった人は 1.4 倍で、前の目標どおり。68種そろえるのはとても大変なので、いまはこのままにしてある
  （強すぎると感じたら、`ZUKAN_BONUS_MAX` か `STAR_RATE` を下げる）。
  ボットのふつうの腕前・いつもの台・1000ゲームずつ（2026-10-09。かざぐるまの直しのあと。赤コイン（÷11,875）。
  「前」は県の台のころのはじめの赤コイン（÷9,500）の数字を8割にしたもの）：

## 赤コインと記録

- 赤コイン＝スコア ÷ 11,875（切り捨て）、1プレイ2,400枚まで。どのマップでも、自分やフレンドのステージでも同じ。
  アプリの `COIN_POINTS`・`COIN_MAX` とマイグレーションの `record_pinball_result`（いまは 0138）の両方に同じ数字がある（変えるときは両方）。
- コインの色の移り変わり：はじめは赤コイン（スコア ÷ 9,500・3,000枚まで。0134）→ 使い道が無かったので青コインにして枚数を8割に
  （9,500 ÷ 0.8 = 11,875、3,000 × 0.8 = 2,400。0136。持っていた赤コインは同じ枚数の青コインに換えた）→ ステージの部品を
  赤コインで買えるようにして、報酬を赤コインにもどした（枚数は青コインのときのまま。2026-10-09、0138）。0136〜0137 のあいだに
  ピンボールでもらった青コインは、そのまま青コインとして残る。
- **赤コインがもらえるのは3つだけ**：ご当地ピンボールのスコア・ホームに降ってくる赤コイン（5秒ごとに 5%。黄色・青とは別。枚数と受け取りの
  決まりは黄色・青と同じ。`claim_home_coin_drop`）・ログイン（1日1回 50枚。`claim_login_bonus`。アプリの `RED_LOGIN_COINS`）。
  使いみちはステージの部品だけ（下の「ステージ」）。
- 記録（`POST /api/games/pinball/score`）でサーバーが確かめること：値の範囲、遊んだ時間のわりに大きすぎない
  （(秒＋30) × 400,000 点まで）、ある台（マップの id）か・遊べるステージ（自分のものか、フレンドが公開しているもの）か、1時間に40回まで
  （API とデータベースの両方。マップとステージあわせて）。同じ round_id の再送は同じ結果を返す（赤コインは1回だけ。前のプレイの再送では付けない）。
  API は、データベースが返したコインの色（`kind`）を画面に返す（0138 より前のデータベースなら青コイン）。
- 記録の `table_id` はマップの id（`default`・`bumper`・`pachinko`・`coaster`）か、ステージなら `stage`（＋`stage_id`）。前の「県の台」の記録（都道府県コード）は
  そのまま残してあり、いつもの台と同じ形だったので、ベスト（`getPinballBests`）とランキングの台の名前ではいつもの台として数える
  （`resolvePinballMapId`）。古い画面から都道府県コードで送られてきた記録も、いつもの台として記録する。
- **マイグレーション 0137・0138 を当てるまでは**、データベースが新しいマップの id・ステージを受けつけない（`INVALID_TABLE`・関数が無い）。
  そのときも API は「準備中」（`ready: false`）を返すので、遊ぶことはできる（コインは付かない）。ステージと部品の欄は、0138 の前は出さない。
  0139 を当てるまでは、データベースの値段は前のまま（お店の表示は新しい値段）で、新しい部品は買えず、新しい部品を置いたステージは保存できない。
- 記録できるスコアは 2 億点まで（`MAX_SCORE`・データベースの決まりも同じ）。うまい人が全部の県（68種）をそろえて育てきると、
  どのマップでも 150ゲームに3〜8回（長いゲーム）こえるので、送るときに 2 億点でとめる（カンスト。赤コインは 2,400 枚の上限が
  ずっと手前の 2,850 万点なので変わらない）。1秒あたりの上限（(秒＋30) × 40 万点）は、いちばん多いゲームでも 26 万点ほどで、届かない
  （2026-10-08、4つのマップで 150ゲームずつ確かめた）。
- ランキングは自分とフレンドだけ。全部の台まとめて、ベストを出した台も出す（今週＝日本時間の月曜0時から／全期間）。
  **ステージのプレイは入れない**（ステージは形が自由なので、ステージごとのランキングにだけ出す）。
- 物理はブラウザで動くので、スコアはどうしても自己申告。赤コインで買えるのはステージの部品だけだが、スコアをごまかされると
  赤コインが増えすぎる（1時間40回 × 2,400枚まで）。気になってきたら、もっと厳しい確かめ方（プレイの入力を送ってサーバーで再生する など）を考える。

  | 回転バー（2本羽根のかざぐるま。羽根34mm・1.8 rad/s。回る向きをえらべる） | 1,500 | 0 | 2 |
  | スピナー（幅40mm の板。玉は当たらずにくぐる） | 1,200 | 0 | 3 |
  | ドロップターゲット（幅28mm。向きをえらべる） | 900 | 0 | 6 |
  | てっぺんランプ（はねはね台のランプ。台の上のほうへ落とす） | 3,600 | 0 | 1 |
  | コースターランプ（ジェットコースター台の交わるランプ） | 5,400 | 0 | 1 |

  買った部品は、どのステージにも何度でも使える（ステージに置くと減るのではなく、持っている数まで置ける）。
  はじめの部品だけで、いつもの台に近いステージ（`starterStage`：バンパー3つ・かざぐるま・ポスト4本）を作れる。
  値段は 2026-10-09 に、どれも3倍にした（ユーザー指定「全体的に価格を上げて」。前はバンパー 300・てっぺんランプ 1,200 など）。
  全部そろえるのに 46,200 枚（前からある部品だけなら 25,200 枚。ふつうの腕前でピンボール約290回ぶん。ログインとホームのコインもある）。
- **向き**（`angle`。度。0 が横、90 がたて。y が下向きなので 30 は右下がりの「＼」、150 は左下がりの「／」）：
  ガイドレール・ゴムのかべは `WALL_ANGLES`（30・45・60・90・120・135・150）。横に近い向きは平らな面に玉が乗って止まるのでえらべない。
  ドロップターゲットは `DROP_ANGLES`（0・30・60・90・120・150。横もえらべる。上に乗った玉も、落ちてきた勢いでたおれる）。
  左右に折り返すと 180 − 向き になる（どちらの一覧も左右対称）。エディターの「向きを変える」は一覧の次の向きにする（置けない向きならそのまま）。
- **置き方の決まり**（`validateStage`。エディター・保存の API・台えらびが同じものを使う）：
  - 部品のまん中は、台の上のほう（x 40〜440・y 168〜424。`STAGE_AREA`）。下半分（フリッパー・スリングショットのあたり）には置けない。
  - **部品どうし・部品と骨組みのすき間は、どこも 31mm 以上**（`STAGE_GAP`。玉の直径は 27mm）。かざぐるまは羽根のとどく円
    （半径 23.5mm。回転バーは 38.5mm）、スリングショットは三角のふち、ガイドレール・ゴムのかべ・ドロップターゲットは線、
    ブロックはひし形のふち、スピナーは両はしの金具までの線（玉は当たらないが、絵が重ならないように）で数える。マップでは「14mm 以下（玉を通さない）」も使っているが、ステージでは使わない
    （たてのかべとポストを 10mm あけると、そのあいだに玉がよりかかって止まる。どの組み合わせも確かめられないので、31mm 以上だけにした）。
  - てっぺんランプの出口（玉が落ちてくる所）から 40mm 以内には置かない。
  - アイテムの場所（自分で動かせる3か所・どのステージも同じ7か所）に部品を重ねない（20mm あける）。アイテムどうしは 44mm あける。
  - 持っている部品の数・ランプをこえない（データベースの `save_pinball_stage` も数える）。
- **エディター**の台は、遊ぶ画面と同じ描画（`pinball-stage-board.tsx`）。形が変わるたびに描画を作りなおす（スマホで1回 数十ms）ので、
  部品を指で動かしている間は作りなおさない（その部品をのぞいた形のまま描き、動かしている部品は上の SVG に簡単な絵で描く。
  バンパーの笠の絵はバンパーの番号で決まるので、動かしている間もほかのバンパーの絵がずれないようにしてある）。
  置ける所の点（`placeableSpots`）は 12mm ごとに `partProblem` をかける。`partProblem` は骨組みの線を四角で先にふるい分けて、
  遠い線は計算しない（結果は同じ。1回 約2ms）。
  部品えらび・ランプえらび・お店の絵（`pinball-part-art.tsx`）も同じ描画で、台を丸ごと描いて一部を切りとる（1枚 十数ms）。
  1枚ずつ間をあけて描き、描いた絵は色ごとにとっておく（開きなおしたとき・色をもどしたときは描かない）。
- 置き方を確かめる場所は3つ：エディター（置けない所には置けず、動かして置けない所ではなすと戻る。置ける所を緑の点で見せる）、
  保存の API（`validateStage`。持っている部品の数も）、データベース（データの形・部品の数・1人6つまで）。データベースを直接呼べば
  すき間の決まりはすりぬけられるが、台えらび（`getPinballStages`）でも `validateStage` をかけて、問題のあるフレンドのステージは出さない
  （自分のステージには「置き方を直してね」と出して、遊べないようにする）。決まりをきびしくしたときも、この方法で古いステージをよける。
- **公開**（`shared`）にすると、フレンドが台えらびの「フレンドのステージ」で遊べる（RLS：自分のものと、フレンドが公開したものだけ見える）。
  ステージのプレイも赤コインがもらえる（マップと同じ換算）。エディターのテストプレイ（保存する前の形）は記録しない・コインも付かない。
- 記録はステージごと（`stage_id`）。ベスト・ランキング（自分とフレンドだけ）・「いちばん」は、**部品の置き方・ランプ・アイテムの場所を
  最後に変えた時刻（`layout_updated_at`）より後のプレイだけ**を数える（名前・見た目・公開だけを変えたときはリセットしない）。
  ステージを消しても、遊んだ記録（赤コインの元）は残る（`stage_id` は空になる）。「遊ばれた回数」は作った人のほかのプレイの数。
- 確かめたこと（2026-10-09）：
  - `node scripts/simulate-pinball.mjs stagefuzz 300 20`：でたらめに作ったステージ（`validateStage` を通るもの。部品の数もでたらめで、
    置ける所をさがして詰めこむ。新しい部品（ガイドレール〜ドロップターゲット）は半分のステージで使う）300こ × 20ゲームで、
    2.3秒以上止まった玉 0回（0.5秒以上は 1ゲーム 0.03回。新しい部品を足す前と同じ）。
    はじめは上の「物理」のかざぐるまの止まりかたが 150こ × 20ゲームで2回あった。
  - `node scripts/simulate-pinball.mjs stagebalance 60 100`：でたらめなステージ 60こ × 100ゲーム（ふつうの腕前）で、ステージごとの
    赤コインの平均は いつもの台（161.8枚）とくらべて 中央 -20%・90% -1%・いちばん多いステージ +34%（100ゲームなので ±10%くらいのゆれもふくむ。
    いちばん多かったステージ（前からある部品だけ・コースターランプ）も、300ゲームでは 171.3枚＝+6%）。
    スコアの多くはアイテム・ショット・制覇から来るので、上の部品を変えても大きくは増えない。はじめのステージ（`stage:starter`）は 152.2枚（300ゲーム）。
    新しい部品のうち点の入るもの（スピナー・ドロップターゲット・回転バー）を、16のステージに置けるだけ足しても（ステージあたり約7こ）、
    60ゲームずつの平均は 149.1 → 146.5枚（-1.7%。ゆれの中）で、稼ぎすぎにはならない。
  - 部品の置き方の決まりを変えたら、`stagefuzz` で長く止まる玉が 0 のままかを確かめる。部品の強さ（バンパーの大きさなど）を変えたら `stagebalance` も。

## 玉の速さ（`GAME_SPEED`）

- 台の上の時間を 0.75 倍で進める（本物の台の 75% の速さ）。物理（玉・フリッパー・バンパー・ランプ）だけが遅くなり、
  形や強さの調整（打ち出しの強さ・フリッパーの狙い）はそのまま使える。ボールセーブなどの秒数は実際の秒のまま。
- ボットの反応のばらつきは実際の秒で持っているので、玉が遅いほど人と同じく狙いやすくなる（シミュレーターに入っている）。
- 試すとき：`PINBALL_SPEED=0.7 node scripts/simulate-pinball.mjs 300 average 8`。ふつうの腕前で
  0.7＝146秒・197枚、0.75＝138秒・200枚、0.8＝125秒・172枚（2026-10-08。はじめの赤コインの数え方（÷9,500）。いまの赤コインはこの8割）。

## 新しいマップを追加するとき

1. `maps.ts` に `MapSpec` を足して `SPECS` に入れる（id は英小文字・数字・_ で32文字まで。データベースの記録にそのまま入る）。
   骨組みは同じなので、書くのはバンパー・かざぐるま・ポスト／くぎ・壁・スリングショット・スタンドアップターゲットの位置・
   アイテムの場所（tier 1・2 の7か所は `SHOT_SPOTS` をそのまま使う）・ランプの道など。上の「マップ」の「作るときにわかったこと」を守る。
2. `themes.ts` の `PINBALL_THEMES` に、同じ id で名前・説明・しかけ・むずかしさ・色・模様・曲・制覇のことばを足す
   （無いと、いつもの台の見た目になる）。台えらび・ルールのページ・ランキングの台の名前は自動で出る。
3. `node scripts/simulate-pinball.mjs gaps <id>`（せまいすき間）・`stuck 600 <id>`（長く止まる 0）・`shotmap <id>`・`plunger <id>`、
   `node scripts/simulate-pinball.mjs 600 all 8 <id>`（ふつうの腕前の赤コインが、いつもの台の ±10% くらい）で確かめて、下の表を足す。
   ステージの見た目にも使えるようにするときは、`stage.ts` の `STAGE_LOOKS` と、マイグレーションの `save_pinball_stage` の
   `look` の一覧の両方に足す（片方だけだと、その見た目のステージを保存できない）。
4. 画面で見て確かめる（ランプのワイヤーがバンパーや風車の上を通らないか・くぎや部品が重なっていないか）。

## 新しい県・アイテムを追加するとき

1. ご当地アイテムは図鑑（`src/lib/collection/items.ts` の `PREF_ITEMS`）とガチャ（`src/lib/gacha/prizes.ts`）に
   入っていれば、自動でどのマップにも出る（犬のすがたは出ない）。床の県の形も、アイテムのある県をまとめて自動で描く。
2. R 以上のアイテムには `skills.ts` の `RECIPES` に名前と種類を足す（足さなくてもレア度で自動のスキルが付く）。
   Lv5 の覚醒は種類ごとに決まっているので、足さなくてよい。
   アイテムを足すと、図鑑ボーナスの割合（持っている種類 ÷ 全部の県の種類）が、いま持っている人は少し下がる。
3. 数字を変えたらシミュレーターを回して、この表を更新する。ルールページは数字を config.ts から出すので直さなくてよい。

## 確かめ方

- `npx tsc --noEmit`・`npm run lint`・`npm run build`
- `node scripts/simulate-pinball.mjs 300 all 8 all`（上のバランスの表。最後の引数はマップ。`all` で全部、書かなければいつもの台）・
  `node scripts/simulate-pinball.mjs stuck 600 all`（玉が止まる場所）・`gaps all`（せまいすき間）・`shotmap <マップ>`・`plunger <マップ>`
- ステージ：`stagefuzz 300 20`（でたらめなステージで玉が長く止まらない）・`stagebalance 60 100`（でたらめなステージで稼げる赤コイン）。
  マップのかわりに `stage:starter`（はじめのステージ）や `stage:<JSON のファイル>`（保存したステージの spec）も渡せる
  （`stuck 100 stage:my.json` など。`validateStage` を通らないものは使わない）
- データベース：`./scripts/verify-rls.sh`（素の PostgreSQL 16 にマイグレーションを当てて RLS・関数を確かめる。ピンボール・赤コイン・
  部品・ステージの項目がある。2026-10-09 の時点で、ピンボールと関係のない項目（歩数・コイン・ガチャ・共有旅・グループ）が main でも 22 件落ちている）
- 集めかたで比べるとき：`PINBALL_LV=5 PINBALL_STARS=5 node scripts/simulate-pinball.mjs 300 average 18`（全部そろえた人は 18 のかわりに 68）
- 物理・ルールのしくみだけを変えたとき（リファクタリングなど）は、いつもの台の `300 all 8`・`stuck`・`shotmap`・`plunger` の出力が
  変える前と1文字も変わらないことを確かめる（シードが同じなら同じ結果になる。マップを作ったときも、この方法でいつもの台が変わっていないことを確かめた）。
- `PINBALL_DEBUG_EXPORT=1` をつけて import すると、何も回さずに中身（`playGame`・`samplePool` など）を `globalThis.__pb` に渡す
  （調べもの用のスクリプトから使う）
- 開発中（`NODE_ENV !== "production"`）は、遊ぶ画面で `window.__pinball`（`game`・`setFlipper`・`launch`・
  `setPlungerPull`）から台を動かせる。Playwright で自動で遊ばせて、画面を撮って確かめられる。
