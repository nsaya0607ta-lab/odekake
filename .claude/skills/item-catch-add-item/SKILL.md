# アイテムキャッチ 新アイテム追加スキル

アイテムキャッチに新しいアイテムを追加する、または既存アイテムの出現重み・スキル数値を調整するときに、
このスキルの手順を**省略せず最後まで**実行すること。特に最後のシミュレーション実行と結果報告は、
数値をまったく変えていないように見える変更（他アイテムのランク内再配分のみ等）でも**毎回必ず行う**。

## 参照ドキュメント（作業前に必ず読む）

1. `docs/item-catch-new-item-checklist.md` — 通常はこれだけで作業できる早見表。追加手順・
   現在の4プール構成・現在の目標プレイ時間・触ってはいけない数値がまとまっている。
2. `docs/minigame-time-balance.md` — 判断に迷ったときだけ、ファイル最上部の直近の
   「【最新確定N】」節（末尾の番号が一番大きいもの）から遡って読む。それより古い節は
   更新前の内容なので参照しない。

## 手順

1. **`src/lib/collection/items.ts`（図鑑本体）に新アイテムを追加する。** ここに無いと
   ミニゲームの`itemPool`に一切登場しない静かなバグになる。
2. **`src/lib/games/item-catch-skills.ts`にルールブック説明文を追加する。**
3. **アイテムの性質に応じて`frenchie-catch-game.tsx`側の分類を決める：**
   - 時間を直接増やすスキル → `TIME_BONUS_ITEM_IDS`に追加し、`LV`テーブルにLv1〜5の秒数
     （単調増加）を追加（`TIME_BONUS_CUTOFF_ITEM_IDS`にも自動的に含まれることを確認）。
   - 出現量アップ系 → `SPAWN_DYNAMICS_ITEM_IDS`に追加し、`LV.xxx_SPAWN`配列を追加。
   - 得点倍率（"○秒間×n"）系 → `SCORE_MULT_IDS`（`simulate-item-catch.mjs`側の定義）に相当する
     8種の仲間として扱い、`SCORE_MULT_DURATION_*`と倍率カーブを既存のレアリティ別カーブに揃える。
   - **それ以外（特殊効果を持たない通常アイテム）** → 上記どれにも該当しない場合は
     `NORMAL_ITEM_IDS`（4つ目の「通常アイテム系プール」）に追加する。
     `DEFAULT_ITEM_SPAWN_WEIGHT`のまま放置しない。
4. **`ITEM_SPAWN_WEIGHTS`の出現重みを決める。** 該当プール（時間増加系／得点倍率系／
   出現量アップ制御系／通常アイテム系）のうち、追加先のランクに既存アイテムがいる場合は
   **「そのランクの予算 ÷ 在籍数（既存＋追加分）」の値をそのまま**、そのランクの全メンバー
   （既存＋追加分）に書き込む（2026-09-03〜、ユーザー指定。10の倍数への丸めは行わない。
   ランク予算自体が10の倍数にならなくてもそのままでよい）。ランク予算・プール総予算自体は
   変えない。既存アイテムがいない未充填ランクの場合は、対応する
   `XXX_UNFILLED_RANK_DOG_WEIGHT`定数からそのランクの予算分を差し引いて新規追加する。
   **Listen to the a-・ナルシストアー・マフィアーの3つだけはどのプールにも属さない単独
   チューニング枠なので、新アイテムをここに混ぜない。**
5. **`scripts/simulate-item-catch.mjs`側を同期する。**
   - `TIME_BONUS_IDS` / `SPAWN_DYNAMICS_IDS` / `SCORE_MULT_IDS` / `NORMAL_ITEM_IDS`のうち
     該当するSetに同じIDを追加する。
   - 未充填ランクに追加した場合は`XXX_UNFILLED_RANK_DOG_WEIGHT`定数も同じ値に更新する。
   - 時間増加系・出現量アップ系のLV配列を追加した場合は、スクリプトの switch-case に
     対応する`addBonusTime(...)`等の分岐を追加する（正規表現抽出だけでは効果は再現されないため）。
6. **`node scripts/simulate-item-catch.mjs 1000 avoid`を実行する。**（2026-09-03〜、ユーザー指定で
   試行回数は毎回1000でよい。8000/20000等の大規模実行や、目標値表との突き合わせ・重みの
   再調整は不要。）
   - 出力の「プール重み予算」行で、変更していないはずのプールの合計（現在は時間増加系2120 /
     得点倍率系400 / 出現量アップ制御系900 / 通常アイテム系6100）が変わっていないか確認する。
   - 500秒超えが0%のままか確認する（0%でなくなったらカットオフ実装ミスを疑う。これだけは
     引き続き確認する）。
7. **`docs/item-catch-new-item-checklist.md`・`docs/minigame-time-balance.md`の該当箇所
   （プール構成表、必要なら新しい「【最新確定N+1】」節）を今回の変更内容と実測値で更新する。**

## 最後に必ずやること：結果報告

作業の最後に、**変更の有無・大小にかかわらず**、直近で実行した
`node scripts/simulate-item-catch.mjs 1000 avoid`の生の実行結果を、Lv1〜5の
秒数平均・中央値・500秒超え％・スコア平均を表にしてユーザーに提示すること。
「数値は変えていないので省略してよい」という判断はしない。ユーザーが結果を見て
気づける状態を毎回作ることが、このスキルの目的そのものである（プレイ時間を目標値に
合わせる調整は不要だが、結果自体は必ず報告する）。
